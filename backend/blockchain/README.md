# GlobeX blockchain boundary

Express calls the existing GlobeX chain adapter through `CHAIN_ADAPTER_URL`.
Private keys, RPC credentials, contract ABI, and `TradeEscrow.sol` stay inside
that adapter process. Express persists returned transaction evidence in
`blockchain_records` and exposes it through `/api/v1/blockchain/*`.

Required adapter contract:

- `GET /health`
- `POST /anchor/trade`
- `POST /escrow/create`
- `POST /escrow/:tradeId/fund`
- `POST /escrow/:tradeId/condition`
- `POST /escrow/:tradeId/release`
- `POST /escrow/:tradeId/dispute`
- `POST /escrow/:tradeId/resolve`
- `POST /escrow/:tradeId/refund`
- `GET /escrow/:tradeId`

Each success response must include `ok: true`; transaction methods should
return `transactionHash`, `blockNumber`, and chain metadata. No fake hashes are
generated by Express.

n8n remains a later orchestration phase. It can call these stable Express
webhooks after the chain adapter is running.
